About This Research Prototype

Learn Depth · Problem ML-T2-061 · Detecting Claims That Require External Verification

Central Research Question

"Can an NLP system recognize when a claim cannot responsibly be accepted without external evidence?"

What this system does NOT do

It does not classify claims as true or false. It classifies whether the claim can be responsibly accepted given the available context, and routes uncertain or high-stakes claims toward evidence retrieval and human review.

Pipeline

Text → sentence segmentation → claim filtering → compound decomposition → linguistic feature engineering → hybrid ML+rule verdict → context-sufficiency & risk scoring → evidence retrieval (TF-IDF) → conflict detection → human review routing.

Datasets

Real, human-annotated data: ~17,600 sentences from the CLEF CheckThat! 2019 shared task (US presidential debates/speeches, 2016–2019), professionally fact-checked and labeled check-worthy or not. Trains a dedicated binary check-worthiness model, whose probability output is blended into the fine-grained classifier as one input feature.

Synthetic seed set (175 examples): weakly-labeled, programmatically-authored claims covering the difficult cases the problem statement names (compound, temporal, conditional, implicit). Trains the fine-grained context_sufficient / needs_verification / high_priority classifier via 5-fold cross-validation. See backend/data/build_seed_dataset_v2.py.

Known limitations

  • The 3-way seed dataset (n≈175) is still weakly-labeled and programmatically generated, though now roughly balanced across labels and blended with a real-data signal (see above) — a documented placeholder for a fully human-annotated 3-way corpus.
  • Local evidence retrieval uses BM25 (with stemming) over whatever context the user supplies. An optional web-search fallback via Groq's groq/compound model (built-in, citation-backed search) is available when a GROQ_API_KEY is configured.
  • Claim extraction uses lightweight regex/rule-based sentence and clause splitting rather than a dependency parser, to stay dependency-light and fully explainable.
